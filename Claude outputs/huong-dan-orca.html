Sổ tay Orca + AI coding agent

Ghi lại toàn bộ quá trình cài đặt, khái niệm và cách dùng Orca cùng Claude Code, Codex, Antigravity CLI trên laptop Windows của bạn (cập nhật 08/11/2026).

1. Tổng quan: mỗi công cụ làm gì?

Hãy hình dung bạn là trưởng nhóm, các AI agent là nhân viên, còn Orca là văn phòng nơi bạn giao việc và theo dõi mọi người.

GitLưu lịch sử code, quản lý nhánh. Là nền móng của mọi thứ.
GitHub CLI (gh)Làm việc với website GitHub từ terminal: đăng nhập, tạo repo, tạo Pull Request.
Claude Code (claude)AI agent của Anthropic, chạy trong terminal, tự đọc, sửa code, chạy lệnh.
Codex (codex)AI agent của OpenAI, tương tự Claude Code, có sandbox trên Windows.
Antigravity CLI (agy)AI agent của Google (thay cho Gemini CLI đã ngừng hỗ trợ tài khoản cá nhân).
Orca“Bảng điều khiển”: tạo nhánh riêng cho từng việc, mở agent trong đó, thông báo, theo dõi hạn mức.
VS CodeTrình soạn code để đọc kỹ hoặc tự sửa tay.
Orca không có AI riêng. Nó chỉ mở các agent (Claude, Codex, agy) và sắp xếp chỗ làm việc cho chúng. Nhánh, worktree, commit, merge đều là của Git. Gỡ Orca thì code và nhánh vẫn còn nguyên.

3. Git trong 5 phút: vở chính và tờ nháp

Hình ảnh dễ nhớ: main là vở chính, chỉ chép bài đã đúng. Mỗi nhánh là một tờ nháp giao cho agent làm thử. Nháp đúng thì chép vào vở (merge), nháp sai thì vứt, vở không sao.
Khái niệmNghĩa đơn giản
RepoThư mục project có Git quản lý (có thư mục ẩn .git).
CommitMột lần “chụp ảnh” lưu lại trạng thái code, kèm lời mô tả. Mỗi commit có mã như c46da48.
Nhánh (branch)Chỉ là một cái tên trỏ vào một commit. Tạo nhánh gần như không tốn gì.
mainNhánh chính: bản code chính thức, luôn chạy được. Không làm việc trực tiếp trên nó.
WorktreeTính năng Git cho phép mở nhiều nhánh cùng lúc, mỗi nhánh một thư mục riêng.
MergeGộp công việc của một nhánh vào nhánh khác (thường là vào main).
Fast-forwardKiểu merge đơn giản nhất: main chỉ việc “dời tên” tới commit mới, không có xung đột.
Push / PullĐẩy commit lên GitHub / kéo commit mới từ GitHub về.

Vòng đời một nhánh

Ctrl+N tạo nhánh "them-du-an"  (tách từ main mới, đã có bài giảng) → … → merge → xóa

Hiểu sơ đồ này trong 5 câu

  1. Bạn tạo thư mục project. Đó là thư mục gốc và là nhánh main.
  2. Bấm Ctrl + N trong Orca: Orca tạo orca\workspaces\<project>\<nhánh>, mỗi nhánh một thư mục.
  3. Trong thư mục nhánh, .git chỉ là file con trỏ về kho ở thư mục gốc. Vì dùng chung kho nên commit ở nhánh được ghi ngay vào kho gốc.
  4. Agent làm việc trong thư mục nhánh. Thư mục gốc chưa thấy file mới.
  5. Về main và merge: Git dời tên main tới commit mới và cập nhật file. Lúc này file mới xuất hiện ở thư mục gốc.
Commit = ghi vào sổ (kho .git). Merge = chép ra vở chính (thư mục gốc).
Không thấy .git trong File Explorer? Vì nó là thư mục ẩn. Bật View → Show → Hidden items để thấy. Chỉ xem, đừng sửa hay xóa gì trong .git.
Vì sao file ở gốc 19.187 byte còn bản trong worktree 19.122 byte?

Chênh đúng 65 byte cho 65 dòng. Do core.autocrlf=true: khi đưa file ra thư mục gốc, Git đổi ký tự xuống dòng sang kiểu Windows (thêm 1 byte mỗi dòng). Nội dung giống hệt, Git coi là một.

6. Quy trình làm việc hằng ngày

  1. Tạo worktree: nhấn Ctrl + N → chọn Project → ô Smart gõ tên việc (không dấu, gạch ngang, ví dụ them-trang-du-an) → chọn Agent → Create worktree. Nếu agent hỏi trust thư mục project: chọn Yes.
  2. Chuẩn bị agent: gõ /model chọn model phù hợp (Sonnet cho việc thường). Nhấn Shift + Tab chọn chế độ quyền (xem mục 8).
  3. Giao việc: gõ yêu cầu rõ ràng. Ví dụ: “Tạo file index.html giới thiệu bản thân, HTML + CSS thuần.” Việc lớn thì gõ /plan trước để agent lập kế hoạch.
  4. Review: mở ⑂ Source Control, bấm từng file xem diff. Kiểm tra có sửa file lạ, link lạ, code thừa không.
  5. Chạy thử: mở tab Terminal trong workspace, ví dụ start index.html. Chưa ưng thì bảo agent sửa tiếp.
  6. Commit: bảo agent “Commit tất cả thay đổi với message phù hợp”, hoặc tự commit trong Source Control. Kiểm tra: git status báo working tree clean.
  7. Merge vào main: bấm workspace main ở sidebar → tab Terminal → git merge HoangDuyet2005/ten-nhanh. Thấy Fast-forward là ổn. Kiểm tra bằng dir và git log --oneline.
  8. Dọn dẹp (khi muốn): chuột phải workspace đã merge → Delete, chọn xóa cả nhánh. Không xóa cũng không sao, nhưng đừng làm tiếp trong worktree đã merge mà quên merge lại.
Không làm việc trực tiếp trên main. Trên main chỉ: merge, git pull, git log, và làm gốc để tạo worktree mới.

Codex

Có sandbox trên Windows (đã cài bản chuẩn, cần Admin một lần). Chế độ quyền hiện tại: Workspace (tự do trong thư mục project, ra ngoài thì hỏi). Đổi bằng /permissions. Codex không hỏi trust thư mục khi mở, nên bạn phải tự cd vào project trước.

Antigravity CLI

Hỏi trust thư mục giống Claude. Đã chọn không chia sẻ / có chia sẻ dữ liệu tùy lúc thiết lập; đổi lại trong settings của agy.

Quy tắc trust thư mục

  • YES thư mục project cụ thể, worktree trong orca\workspaces.
  • NO C:\WINDOWS\System32, C:\Users\LENOVO, C:\Users.
PowerShell quyền Admin luôn mở ở System32. Muốn chạy agent ngoài Orca thì cd vào project trước. Terminal bên trong Orca chạy quyền thường và mở sẵn ở thư mục workspace.

11. Đưa lên GitHub và làm bằng Pull Request

Repo AI_In_Action hiện chỉ có trên máy. Khi muốn sao lưu và làm kiểu chuyên nghiệp:

Lần đầu: tạo repo trên GitHub

cd ~\AI_In_Action
gh repo create AI_In_Action --private --source . --push

Hoặc bảo agent ở workspace main: “Tạo repo private trên GitHub tên AI_In_Action và đẩy nhánh main lên.” (Nút Publish Branch trong Source Control cũng dùng để đẩy nhánh lên.)

Mỗi việc sau đó: Pull Request thay cho merge trên máy

  1. Làm việc trong worktree như bình thường, commit.
  2. Bảo agent: “Đẩy nhánh lên GitHub và tạo Pull Request” (agent dùng git push + gh pr create).
  3. Vào GitHub xem PR, bấm Merge.
  4. Ở workspace main trên máy: git pull để lấy bản mới.
Trước lần git push đầu tiên của mỗi project: kiểm tra .gitignore đã chặn .env, khóa API, node_modules/, .venv/.

12. Kết hợp VS Code

  • Mở project: File → Open Folder. Terminal: Ctrl + `, gõ claude / codex / agy.
  • Extension chính thức: Claude Code, Codex (dùng chung tài khoản đã đăng nhập ở CLI).
  • Mở một worktree của Orca trong VS Code: trong terminal của worktree gõ code .
  • VS Code không tự tạo worktree. Làm trong VS Code thì tự tạo nhánh trước: git switch -c ten-viec.
  • Codex chạy ngoài Orca vẫn dùng daemon mặc định; trong Orca thì không. Hai bên không ảnh hưởng nhau.

13. Xử lý sự cố đã gặp

Codex: “an existing daemon release has different contents”

Daemon bản cũ còn sót (hay gặp sau khi cập nhật Codex).

taskkill /F /IM codex.exe
Remove-Item ~\.codex\packages\app-server-daemon, ~\.codex\app-server-daemon -Recurse -Force

Hoặc dùng tạm: codex --no-daemon

Codex: “Missing optional dependency @openai/codex-win32-x64” 
npm uninstall -g @openai/codex
npm cache clean --force
npm install -g @openai/codex@latest --include=optional

Lưu ý: gõ nhầm npm i codex sẽ cài một gói khác không liên quan, vào thư mục hiện tại.

Lệnh “is not recognized” sau khi cài (claude, gh, agy…)

Đóng và mở lại PowerShell để nạp PATH mới. Claude Code native cần PATH có %USERPROFILE%\.local\bin:

$p = [Environment]::GetEnvironmentVariable("Path", "User")
if ($p -notlike "*\.local\bin*") {
  [Environment]::SetEnvironmentVariable("Path", "$p;$env:USERPROFILE\.local\bin", "User")
}
Gemini CLI: “This client is no longer supported…”

Google đã ngừng Gemini CLI cho tài khoản cá nhân. Dùng agy (Antigravity CLI) thay thế.

winget báo “already installed” dù lệnh không chạy 
winget install --id GitHub.cli --force
warning: LF will be replaced by CRLF

Không phải lỗi. Là cài đặt core.autocrlf=true đang làm việc.

Orca không thấy project trong danh sách import

Thư mục chưa phải git repo. Chạy git init, git add ., git commit -m "init" rồi thêm lại.

“Update installed · Restart to update” trong Claude Code

Claude Code tự cập nhật. Gõ /exit rồi mở lại agent để dùng bản mới.

14. Quy tắc vàng

  1. Mỗi việc một worktree, không làm thẳng trên main.
  2. Đặt tên nhánh theo việc, không dấu: feat/trang-du-an, fix/loi-menu.
  3. Chỉ trust thư mục project, không bao giờ System32 hay cả thư mục người dùng.
  4. Yolo mode tắt; không dùng bypass permissions.
  5. Review diff trước khi merge: AI có thể sai.
  6. Hai agent không cùng sửa một file cùng lúc.
  7. Kiểm tra .gitignore chặn .env trước khi push.
  8. Code lạ (repo tải về, người khác gửi): dùng manual hoặc plan mode.
  9. Theo dõi hạn mức, dùng Sonnet cho việc thường.
  10. Không chia sẻ file đăng nhập và mã đăng nhập một lần.

Git hay dùng

git status                         # có gì thay đổi / chưa commit
git log --oneline                  # lịch sử commit
git branch                         # các nhánh
git worktree list                  # các worktree và thư mục của chúng
git add .                          # chọn tất cả thay đổi
git commit -m "mô tả"              # lưu một commit
git merge HoangDuyet2005/ten-nhanh # gộp nhánh vào nhánh hiện tại (đứng ở main)
git switch -c ten-nhanh            # tạo nhánh mới (khi làm ngoài Orca)
git pull / git push                # lấy về / đẩy lên GitHub
start ten-file.html                # mở file bằng trình duyệt
